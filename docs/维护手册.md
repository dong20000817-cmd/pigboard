## 一、日常：什么都不用做

每天 **07:45（北京时间）** GitHub 的服务器会自动：

1. 抓五个模块的数据；
2. 有变化才改写看板（**没变化就不提交、也不动页面**）；
3. 重新发布到上面的网址。

**你的 Mac 可以一直关着。** 手机也随时能看。

> 想立刻看最新数据？不需要等定时。直接刷新页面即可 —— 云端页面本身是上次构建的结果；
> 想强制重建就点 Actions →「每日更新看板」→ Run workflow。

## 二、只有这两种情况需要你动手

### 情况 1：更新「冻品库容率」或「淘汰母猪比价」

这两个是指标是第三方付费数据，没有免费接口，必须人工录入。

```bash
cd ~/PigBoard
# 1) 用任意编辑器改这两个文件，填新数值并写清 source_url / publish_date
open data/registry/frozen_inventory.json
open data/registry/cull_sow_ratio.json

# 2) 推送（会自动触发云端重建）
git pull --rebase
git add -A
git commit -m "data: 更新冻品库容率"
git push
```

推送后约 2 分钟，网页自动更新。

### 情况 2：能繁母猪有新的官方发布

**通常不用管** —— 云端会自动扫农业农村部官方表，季末月一发布就自动带出来。

只有在官方页面结构改版、自动抓取失败时才需要手动补。看网页顶部有没有出现「数据源异常」告警即可。

## 三、出问题怎么查

| 现象 | 查看位置 |
|---|---|
| 网页没更新 | Actions 页面看最近一次运行是否绿色 |
| 某模块显示「数据源异常」 | 网页顶部黄色告警条，写着哪个源失败 |
| 数据看着不对 | 点每张卡片下的「口径与来源」，有原始 URL 和发布日期 |
| 想回退 | `git log` 找到上一个提交，`git revert <sha>` 后 push |

**"没有新数据就不动看板"** 这条承诺有自动化测试守护：

```bash
cd ~/PigBoard && python3 selftest.py    # 17 项，应全部通过
```

## 五、本机与云端的关系（唯一要注意的坑）

本机的 `~/PigBoard` 和 GitHub 仓库是**两份共用同一个 git 历史**的代码：

- 云端每天可能产生数据提交；
- 你本地改完东西推送前，**先 `git pull --rebase`**，否则会被拒绝。

就这一条，记住就行。

## 六、想停掉云端

仓库 → Settings → Pages → 直接关掉即可；或在 Actions 里 Disable workflow。
