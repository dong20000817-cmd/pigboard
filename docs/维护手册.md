## 一、日常：什么都不用做

两条自动线在跑，谁先看到新数据谁先更新，抓不到就保持上一期：

| 谁 | 什么时候 | 干什么 |
|---|---|---|
| GitHub 云端 | 每天 **07:45** | 抓行情/期货/第三方样本 → 有变化才改写看板 → 重新发布 |
| **你的 Mac**（开机时） | 07:45 / 09:30 / 12:30 / 15:30 / 17:30 / 21:30 | 同上，**而且是能繁母猪官方数据的唯一可靠来源** |

**想立刻更新：点看板标题下面的「立即更新」按钮。**

- 本机 `http://127.0.0.1:8787/` 或手机同 Wi-Fi 打开 `http://<Mac的IP>:8787/` → 真的会去抓一遍，页面显示「更新中 N 秒」，结束自动刷新；
- 云端网址上的按钮是灰的：静态页没法让 Mac 干活，点了会提示你去本机版。

> 官方能繁母猪：农业农村部官网（moa.gov.cn）在境外网络经常连不上，所以**云端的
> GitHub 服务器抓不到新季度**，是 Mac 抓到后写进 `data/registry/sow_inventory.json`，
> 再推上去的。Mac 长期关机会导致新季度迟迟不出现——开着机最省心。

## 二、只有这两种情况需要你动手

### 情况 1：更新「冻品库容率」或「淘汰母猪比价」

这两个是第三方付费口径，**没有免费接口**。看板每天会自动扫一遍公开转载
（中国养猪网、猪好多网），只有「文中明示机构 + 不是预测值 + 落在合理区间」才收录；
抓不到就保持上一期，不会编造。

看板顶部的「公开源扫描 10-30 12:45：巡检 4 篇 · 新增冻品 0 / 比价 0」就是这件事的结果。

真要手工补一条时：

```bash
cd ~/PigBoard
# 1) 用任意编辑器改这两个文件，填新数值并写清 source_url / publish_date
open data/registry/frozen_inventory.json
open data/registry/cull_sow_ratio.json

# 2) 推送（会自动触发云端重建）
git pull --rebase
git add -A
git commit -m "data: 更新冻品库容率"
git push
```

推送后约 2 分钟，网页自动更新。

### 情况 2：能繁母猪有新的官方发布

**通常不用管。** Mac 每次巡检都会重扫最近 3 个月的官方页面，季末月一发布就自动带出来，
并写进登记库留档。实测：2026 年三季度数据 10-29 下午发布，当天晚上就已上板。

只有官方页面改版、自动抓取失败时才需要手动补。看网页顶部有没有「数据源异常」告警即可。
页面上的「下一期官方发布」也是按最新入库季度自动推算的，不用手工改。

## 三、出问题怎么查

| 现象 | 查看位置 |
|---|---|
| 网页没更新 | Actions 页面看最近一次运行是否绿色 |
| 某模块显示「数据源异常」 | 网页顶部黄色告警条，写着哪个源失败 |
| 数据看着不对 | 点每张卡片下的「口径与来源」，有原始 URL 和发布日期 |
| 想回退 | `git log` 找到上一个提交，`git revert <sha>` 后 push |

**"没有新数据就不动看板"** 这条承诺有自动化测试守护：

```bash
cd ~/PigBoard && python3 selftest.py    # 17 项，应全部通过
```

## 五、本机与云端的关系（唯一要注意的坑）

本机的 `~/PigBoard` 和 GitHub 仓库是**两份共用同一个 git 历史**的代码：

- 云端每天可能产生数据提交；
- 你本地改完东西推送前，**先 `git pull --rebase`**，否则会被拒绝。

就这一条，记住就行。
