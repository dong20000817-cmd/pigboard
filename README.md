# 生猪市场看板（私有部署 · iPhone 可用）

一个**本地私有、静默运行**的生猪市场数据看板。核心约定只有一条：

> **同一口径留痕；没有新数据，就不动看板。**

- 本机地址：<http://127.0.0.1:8787/>
- 部署位置：`/Users/dqy/PigBoard`
- 自动更新：每天 **07:45**（另在 09:30 / 12:30 / 15:30 / 17:30 / 21:30 各巡检一次）
- iPhone：通过 **Tailscale 私有组网**随时随地访问，可「添加到主屏幕」当 App 用
  （访问地址：`bash setup_tailscale.sh` 打印）

## 二、iPhone 部署（Tailscale，2 步）

### 第 1 步：Mac 安装并登录 Tailscale

安装包已下载好（Tailscale Inc. 签名 + Apple 公证）：

```
双击打开  ~/Downloads/Tailscale-1.104.1-macos.pkg
```

装完后从「应用程序」启动 Tailscale，用邮箱登录。

### 第 2 步：拿到 iPhone 访问地址

```bash
cd ~/PigBoard
bash setup_tailscale.sh
```

输出形如：

```
① http://macbook-air.<你的tailnet>.ts.net:8787/
② http://100.106.83.98:8787/
```

> 这两个地址**已经可以直接用**。Tailscale 会把 Mac 的私有 IP 暴露给同一账号下的设备，
> 而看板服务监听 `0.0.0.0`，所以不需要额外配置。

### 第 3 步：iPhone

1. App Store 搜索 **Tailscale**，安装并用**同一个账号**登录；
2. **打开 Tailscale App 确认显示 Connected**（否则地址打不开）；
3. Safari 打开上面任一地址 → 分享 → **添加到主屏幕** → 桌面出现「生猪看板」图标，全屏运行。

<details>
<summary>可选：开启 HTTPS（更漂亮的网址 + 可离线缓存）</summary>

默认的 `http://` 已完全可用。若想要 `https://`：

```bash
bash setup_tailscale.sh https
```

若提示 `your Tailscale account does not support getting TLS certs`，说明 tailnet 未启用证书，
需要**手动开启一次**：

1. 浏览器打开 <https://login.tailscale.com/admin/dns>
2. 页面下方找到 **HTTPS Certificates** → 点 **Enable**
3. 回终端重跑 `bash setup_tailscale.sh https`

> ⚠ **已知坑**：在未启用证书时，原生的 `tailscale serve --bg 8787` 会**无限期挂起**
> （不报错、不返回）。本项目脚本已内置硬超时，会在 25 秒内失败并给出上述指引，不会卡住。

开启 HTTPS 的好处：iOS 只允许 HTTPS 页面注册 Service Worker，因此只有 HTTPS 才能离线缓存。
</details>

<details>
<summary>备选：只在同一 Wi-Fi 下访问（不装 Tailscale）</summary>

```bash
python3 serve.py --lan --port 8787
```
然后 iPhone 浏览器打开 `http://<Mac的局域网IP>:8787/`。缺点：出门用 4G/5G 就看不了，且是明文 HTTP。
</details>

## 二·五、手机端：离线查看与「不依赖 Mac」

### 三种可用形态

| 形态 | 手机能看到 | 数据新鲜度 | 前提 |
|---|---|---|---|
| 局域网 / Tailscale 直连 | 是 | 每天 07:45 自动更新 | **Mac 必须开机** |
| ＋离线缓存 | **Mac 关机也能看** | 最后一次同步时的快照 | 开启 Tailscale HTTPS（一次点击） |
| ＋云端托管 | 随时 | 每天自动更新，**无需 Mac** | 一个 GitHub 账号 |

> 只要数据是从某台机器抓的，就一定有台「开着的机器」。云端托管只是把那台机器换成 GitHub 的服务器。
> 详见 [云端部署_GitHub-Pages.md](docs/云端部署_GitHub-Pages.md)。

### 开启离线缓存（1 次点击）

看板已内置 Service Worker：在线时用网络最新版本，离线时回落缓存，并显示
「⚠ 离线 · 正在显示最后一次同步的内容」提示条。

但 iOS 只允许 **HTTPS** 页面注册 Service Worker，所以需要先开 Tailscale 的证书：

1. <https://login.tailscale.com/admin/dns> → 页面下方 **HTTPS Certificates** → **Enable**
2. 终端执行 `bash ~/PigBoard/setup_tailscale.sh https`
3. iPhone 用打印出的 `https://...` 地址重新「添加到主屏幕」

之后即使 Mac 关机、iPhone 开飞行模式，点桌面图标仍能打开最后一次同步的完整看板。

## 四、"无变化不改动"是怎么实现的

`pipeline.py` 每次运行：

1. 采集五个模块 → 归一化；
2. 对每个模块的数据负载单独计算 `value_hash`（**剔除时间戳、告警文案、以及 `value_hash` 自身**，
   避免自指导致反复改写）；
3. 与 `data/snapshot.json` 逐模块比对：
   - **全部哈希相同** → 判定「无变化」：**不写快照、不重建 `web/index.html`、不产生变更条目**，
     只在 `data/heartbeat.json` 记一次巡检心跳；
   - **任一哈希变化** → 写快照、写变更留痕（含变化幅度与简短说明）、重建看板。
4. 单一数据源失败时**沿用上一期数据并标注 `stale`**，看板顶部弹告警；
   采集失败本身**不算数据变化**，故障持续期间不会反复改写看板。

**这条承诺由自检脚本持续守护**（在临时副本中做故障注入，不碰正式数据）：

```bash
python3 selftest.py
```

```
[1] 首次采集 …………………………… ✅ 生成看板 / 快照 / 变更留痕
[2] 无变化时必须原样不动 ………… ✅ 判定'无新数据' / 内容未变 / mtime 未变
[3] 数据源故障时沿用上一期并告警 … ✅ stale 告警 / 数值保留
[4] 故障持续时不得反复改写看板 …… ✅ 未改写
[5] 数据源恢复 ……………………… ✅ 告警解除 / 重新稳定
[6] 变更留痕必须准确分类 ………… ✅ first_seen / source_error / source_recovered
────────────────────────────────────────
通过 17 项，失败 0 项
```

## 七、口径纪律（为什么这样设计）

1. **单位强制统一**：生猪价格一律 `元/公斤`（页面同时给出 `元/斤` 换算）。
   淘汰母猪比价的分子分母必须同为 `元/公斤`，若来源以 `元/斤` 报出须先 ×2。
2. **"库容量" ≠ "库容率"**：绝对库存量（吨/千克）不进入库容率序列。
3. **官方环比 vs 算术环比**：例如 2026Q1 官方环比 −1.5%，由相邻两期算术推算为 −1.44%。
   差异源于分母口径，看板**以官方值为准并保留算术值备查**。
4. **同机构才能成序列**：卓创样本与钢联样本的冻品库容率相差 10 个百分点以上，**绝不拼接**。
5. **第三方样本 ≠ 官方**：冻品库容率不存在官方口径，看板顶部常驻口径提示。
6. **冲突必须暴露**：Mysteel 自身 2026-02 预测全年库容率均值 19.09%，与 7–10 月各周报
   引用的 32%~33% 不兼容 —— 看板以醒目区块提示，不掩盖。

## 九、macOS 注意事项

- **为什么装在 `~/PigBoard` 而不是桌面**：macOS 的 TCC 隐私保护禁止 launchd 启动的进程
  读取 `~/Desktop`、`~/Documents`、`~/Downloads`（实测报 `Operation not permitted`）。
  放在主目录下，定时任务才能无人值守运行。
- **Mac 休眠时**：launchd 会在唤醒后补跑错过的任务。若希望 Mac 每天 07:40 自动唤醒：

  ```bash
  sudo pmset repeat wakeorpoweron MTWRFSU 07:40:00
  ```

- **服务常驻**：`com.pigboard.serve` 带 `KeepAlive`，异常退出会自动重启。
